# 查本会话消息记录 Skill

## 它解决什么

你在钉钉里收到的**不是**这个会话的全部。群里没 @ 你的消息会被 `group_gate` 挡掉，
不会进你的上下文——包括别人刚发的那张图。真实事故：有人发了一张考勤表截图（没 @ 你），
下一条才 @ 你问「这个图你统计下」，而你手上只有「这个图你统计下」六个字。

这些消息其实都落盘了。用本 skill 查回来。

## 命令

`--conv <会话id>` **必填**，值就在你的 system prompt 里（`本次对话所在的钉钉会话 conv_id = …`）。
conv_id 和 msg_id 含 `+ / =`，**必须用单引号包起来**。

```bash
# 最近的消息（默认最新 30 条 / 近 2 天）
python3 bin/custom/convq.py recent --conv 'cid…=' [--limit 30] [--days 2] [--json]

# 按关键词搜；**正文和图片识别文本都会搜**
python3 bin/custom/convq.py search '预算' --conv 'cid…=' [--limit 20] [--days 7]

# 一条消息的全文（recent 截断后的出口）
python3 bin/custom/convq.py msg 'msg…==' --conv 'cid…='

# 图片内容。没识别过就现在识别，**会阻塞等它**（最多 150 秒）
python3 bin/custom/convq.py image 'msg…==' --conv 'cid…='
```

## recent 的输出怎么读

```
会话 cid…=｜近 2 天，下面是最新 30 条（时间正序）
时区 Asia/Shanghai；「我」= 数字员工自己发的；发送人是显示名不是 userId，可能重名

[08-18 14:27:45 · 21分钟前] 张三: [图片] msg=msgIMG7bQ==
    └ 图片内容(OCR): 8月考勤表｜张三 迟到2次…（共 475 字，全文：… msg 'msgIMG7bQ==' …）
[08-18 14:28:12 · 20分钟前] 张三: @一粟 这个图你统计下 msg=msgASKx1==
    └ 主管裁决: rewrite by 朱鸿 → 「张三 8 月迟到 2 次」
[08-18 14:34:03 · 14分钟前] 我: 张三 8 月迟到 2 次 msg=msg47LA+ub==
```

- **「我」是你自己发的**。别把自己过去的回复当成别人的主张去反驳。
- `└ 图片内容(OCR)` 是那张图的识别结果，挂在它所属的消息下面。
- `└ 主管裁决` 是主管当时对这条消息的处理口径 —— 同类问题优先照这个口径答。
- `msg=xxx` 是消息 id，拿它去 `msg` / `image` 子命令定点取。
- 时间给了绝对值和相对值两种，「刚才」用相对的解。

## 边界

- **只能查当前会话**。没有"查所有会话"的用法，也没有列举会话的子命令。
- 输出有上限（默认最多 30 条、单条 300 字、整体 24000 字节）。被截断时**一定会有
  一行尾注告诉你还有多少没显示** —— 看到尾注就说明还有内容，别当成"就这些了"。
- 只读，不会改任何东西。

## 退出码

| 码 | 含义 | 怎么办 |
|---|---|---|
| 0 | 成功 | — |
| 2 | 参数错 | 多半是漏了 `--conv` 或引号没加 |
| 3 | 图片识别失败 | stderr 里有可操作建议（请对方重发 / 请对方打字发） |
| 4 | 查无此消息 | msg_id 抄错了，或它不在这个会话里 |
| 5 | 等识别超时 | 有别的进程在识别同一张图，**稍后原样重跑一次**即可 |

## 用法纪律

- **不要直接 `cat` / `grep` `knowledge/messages/` 下的 jsonl。** 裸读拿到的是 epoch
  秒、以及消息/识别结果/裁决三种散落的记录类型，要自己对 id，很容易读错。本工具已经
  把它们 join 好、时间也渲染好了。
- 上下文不足以回答时**先查再答**；查不到就直说查不到，不要编。
- `image` 会阻塞最多 150 秒。**别一口气连着串三四个** —— 你自己的空闲预算是 300 秒。
- 要统计/算数时加 `--json`，拿结构化记录比读散文可靠。
