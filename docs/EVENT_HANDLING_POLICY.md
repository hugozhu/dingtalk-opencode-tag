# 数字员工事件消息处理规范

数字员工在群聊/私聊中会收到各类自动化事件推送（监控告警、定时数据、系统通知等）。
本规范定义**分类 → 过滤 → 升级**的处理策略，避免噪声淹没真正需要人关注的信号。

## 核心原则

1. **默认静默**：事件消息不主动回应，除非命中升级条件。
2. **分级响应**：按事件类型和严重程度分层处理，不同层有不同的升级阈值。
3. **不臆造紧急**：常规推送 ≠ 异常，不要对正常数据做过度解读。
4. **可配置**：规则持久化在本文档，FDE 可按业务调整。

## 事件分类

| 类别 | 示例 | 默认策略 |
|------|------|----------|
| **安全告警** | SSH 暴力破解封禁、fail2ban、防火墙拦截 | 静默忽略（系统已自动处置） |
| **监控告警** | 服务不可达、代理失败、磁盘满、进程崩溃 | 连续 ≥6h 未恢复 → 升级提醒 |
| **数据推送** | 汇率、股价、BTC 价格、天气 | 常规忽略；**异常波动 → 立即告警** |
| **新闻/资讯推送** | AI 新闻日报、行业热点摘要、定时资讯汇总 | **不忽略**，正常呈现/简要点评 |
| **状态通知** | 定时截图、设备在线心跳、部署成功/失败 | 静默忽略 |
| **人工指令** | @数字员工 + 明确任务 | 立即响应 |

## 升级规则

### 监控告警：连续超时升级

- 同一问题（同设备 + 同服务）**连续报警超过 6 小时**未恢复 → 主动提醒用户。
- 提醒内容：问题摘要 + 首次报警时间 + 已持续时长 + 建议排查步骤。
- 中间偶发恢复再报警 → 计时重置。

### 数据推送：波动阈值告警

- 常规推送（价格在正常区间波动）→ 忽略。
- **异常波动**触发告警（满足任一）：
  - 单次推送较上一次变化 ≥ **5%**
  - 24h 内累计变化 ≥ **10%**
  - 出现数据源异常（如 volume=0 但价格正常，连续 3 次）→ 提示数据源可能故障
- 告警内容：标的 + 当前值 + 变化幅度 + 对比基准。

### 安全告警：永久静默

- SSH 封禁、fail2ban 等**系统已自动处置**的安全事件 → 永远忽略。
- 例外：同一来源 IP 被封禁 ≥ **10 次/天**（可能暗示定向攻击）→ 每日汇总提醒一次。

## 响应格式

升级告警时使用统一格式：

```
⚠️ [类别] 简要描述
- 设备/来源：xxx
- 首次出现：HH:MM
- 已持续：Xh Ym
- 当前状态：xxx
- 建议：1. ... 2. ...
```

## 配置覆盖

用户可通过对话指令临时或永久调整规则：

- 临时："接下来 2 小时忽略所有告警" → 会话内生效。
- 永久："把 BTC 波动阈值改成 3%" → 更新本文档对应数值。
